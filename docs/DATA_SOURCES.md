# Data sources

## 1. Synthetic demonstration data (used by default)

Everything shown by default is **synthetic**: nine fictional locations, eleven service streams, 364 days (6 Oct 2025 – 4 Oct 2026), seed 42. Generated by `backend/silence_engine/data_generator.py`; written to `data/synthetic/observations.csv`, `data/synthetic/manifest.json` and, separately, `data/synthetic/ground_truth_labels.json`.

| Site | Region | Streams (typical daily volume) | Notes |
|---|---|---|---|
| Northgate Community Clinic | North | primary care (~220), vaccination (~48) | Saturday half-day; flu-season peak |
| Riverside Benefits Office | Central | benefits applications (~85), inquiries (~140) | Weekdays only |
| Eastfield Food Distribution Hub | East | food distribution (~125) | Mon–Sat |
| Harbor Street Pharmacy Outreach | Central | pharmacy dispensing (~175) | 7 days, stays open on holidays |
| Millbrook Rural Health Post | Rural | primary care (~15) | Low volume |
| Central Library Digital Services | Central | digital assistance (~38) | Mon–Sat |
| Westside Water Point | West | water distribution (~410) | 7 days, summer peak, essential |
| Hillcrest Mobile Clinic | Rural | mobile clinic (~7) | Tue/Thu/Sat only, very low volume |
| Southbank Pop-up Support Hub | East | community support (~55) | Opens on day 210 — tests "insufficient history" |

**Background process**: weekday factors, annual seasonality, slight trends, gamma-Poisson (over-dispersed) counts, regional storms (more in winter), occasional transport disruptions and minor outages with small effects, four public holidays (non-essential services close), 1% random heartbeat loss, 2% short uploads, 0.4% random missing days, 0.3% malformed counts, 0.8% duplicate rows (some conflicting), occasional outdated schedule entries, and reporting delays of 0–3 days for ~14% of records.

**Injected events** (labels kept separately; 176 events for seed 42):

| Class | Subtypes | What changes |
|---|---|---|
| Access gap | weather, transport, service outage (incl. unplanned full closure), unexplained | Real demand falls 35–100%; feed healthy; matching context flag except "unexplained" |
| Reporting failure | dropout, zero-fill, stale flatline, partial uploads, covert | Real activity normal; the *record* is missing, zero-filled, frozen, partial — or silently reduced with no feed trace ("covert", deliberately undetectable) |
| Ambiguous | mixed signals | Real 25–55% decline **and** partial feed degradation, sometimes mild context |
| Scheduled closure | public holiday, training, maintenance, relocation | Schedule marks normally-open days closed |
| Normal variation | benign demand lull | 8–22% dip, healthy feed |

Six "showcase" events are placed deliberately in the final weeks so the dashboard has current examples. They are labelled and evaluated exactly like the others.

**Reproducibility**: each stream has its own `random.Random` seeded from the global seed. The SHA-256 of the raw records for seed 42 is `fd71e981ade10e5747117565c82ac1b6fcf31378c6a38211a0ce80fdd29c63e5` (identical on CPython 3.11.4, 3.13.9 and 3.14.7 on macOS arm64).

## 2. Candidate open datasets (not downloaded; documentation only)

No public dataset was downloaded or used for any result in this repository. The sources below were checked on 17 Oct 2026 by reading their public pages or metadata; licence details that could not be confirmed are marked as such. None of them contains labels saying a service failed — any real-world use would need its own verification.

### NHS England — Appointments in General Practice (service activity)

- URL: <https://digital.nhs.uk/data-and-information/publications/statistical/appointments-in-general-practice>
- Publisher: NHS England (formerly NHS Digital).
- What it is: monthly official statistics on GP appointments (attended / did not attend), published at national, regional, ICB and practice level. Built from GP practice and PCN appointment systems only, so it does not capture all primary-care work. No patient-identifiable data.
- Fit: a real aggregate service-activity series per location, close to this project's schema (monthly rather than daily).
- Licence: **not confirmed here** (the official page returned HTTP 403 to automated fetching; details were read from an OpenPrescribing mirror of the NHS pages). Check the official page before use.
- Relevant caveat for this project: the mirror of the March 2026 release notes that data from two appointment-system suppliers was excluded for that month because of a data-pipeline issue — exactly the kind of reporting artefact that must not be mistaken for a fall in appointments.
- Preprocessing sketch: aggregate the practice-level file to `service_date` = first day of month, `site_id` = practice code, `service_type` = `primary_care`, `observed_count` = appointments; leave counts blank where a practice did not submit. Monthly cadence needs `lookback_weeks` re-interpreted as months (future work).

### NYC Open Data — 311 Service Requests (demand signal)

- URL: <https://data.cityofnewyork.us/Social-Services/311-Service-Requests-from-2010-to-Present/erm2-nwe9> (portal title now "311 Service Requests from 2020 to Present").
- Publisher: City of New York, NYC Open Data portal (attribution "311"). Metadata reports daily automated updates.
- Fields (from the metadata API): `unique_key`, `created_date`, `closed_date`, `agency`, `complaint_type`, `descriptor`, `incident_zip`, `incident_address`, … — row-level requests with addresses.
- Licence: the dataset metadata does not state one; NYC Open Data terms of use apply. **Verify before use.**
- Fit and caution: requests are *demand*, not service delivery, and rows include addresses. Aggregate to counts per agency (or per zip) per day **before** import and drop addresses; never import row-level data into this tool.

### Open-Meteo Historical Weather API (context)

- URL: <https://open-meteo.com/en/docs/historical-weather-api>
- Provides hourly and daily variables (precipitation, rain, snowfall, WMO weather code, temperature…) from ERA5 (from 1940, ~25 km), ERA5-Land and ECMWF IFS; ERA5 is updated with about a five-day delay.
- No API key needed for standard use. The page lists non-commercial, commercial and self-hosted licences and asks users to cite Open-Meteo and the underlying datasets (Copernicus). Check the licence page for exact terms.
- Fit: map the daily WMO weather code and precipitation/snowfall to the 0–3 `weather_severity` index per site location.

### NOAA NCEI — GHCN-Daily (context)

- URL: <https://www.ncei.noaa.gov/products/land-based-station/global-historical-climatology-network-daily>
- Daily max/min temperature, precipitation, snowfall and snow depth from 100,000+ stations in 180 countries; not bias-adjusted; downloadable as station files.
- Licence/terms: not stated on the product page (US federal data is typically public domain, but **this was not verified**).
- Fit: station-based alternative to Open-Meteo for `weather_severity`.

## 3. Import pathway

`POST /api/import-csv` (or `python manage.py import-csv FILE --mode append|replace`) accepts UTF-8 CSV with a header row. `GET /api/schema` and the Platform page list the columns:

| Column | Required | Notes |
|---|---|---|
| `service_date` | yes | `YYYY-MM-DD` |
| `site_id` | yes | `[A-Za-z0-9_.-]{1,40}` |
| `service_type` | yes | `[a-z0-9_]{1,40}` |
| `observed_count` | no | integer ≥ 0; **blank = not reported (missing)**; anything else is kept as *malformed* |
| `scheduled_open` | no | boolean, default true |
| `feed_heartbeat_received`, `feed_last_seen`, `report_received_at`, `batches_expected`, `batches_received` | no | feed metadata; without it the engine can only detect missing records, not subtler feed failures |
| `weather_severity` (0–3), `transport_disruption`, `reported_outage` | no | context |
| `site_name`, `region` | no | display and peer comparison |

Rows with an invalid date, site or service are rejected with row-level messages; malformed optional values are dropped with a warning. `append` keeps existing data (mode becomes "mixed"); `replace` clears everything, including the synthetic demo and its evaluation. Imported data has no ground truth, so the evaluation page keeps reporting on the synthetic streams only.
